# Синтетические данные

Только вымышленные записи. Признаки, что данные реальные (запрещено):
настоящие ФИО, телефоны, e-mail, ИНН/СНИЛС/паспорта, номера счетов и договоров,
внутренние адреса и названия контрагентов.

Правила:
- имена вида «Клиент-001», суммы и даты — случайные;
- в каждом файле — комментарий, какой случай он моделирует (норма / исключение / ошибка);
- реальные выгрузки сюда не кладём даже временно.

## Состав (демо-процесс «Баг-репорты по ручному тестированию»)

| Файл | Что моделирует |
|---|---|
| `test-run-RUN-2026-11-16-01.csv` | Экспорт тест-рана: 10 кейсов, 6 Passed, 3 Failed, 1 Blocked |
| `existing-bugs.csv` | Открытые баги в трекере — для поиска дублей |
| `run-logs/TC-1042.txt` | Норма: ошибка 500 с причиной в логе → новый баг |
| `run-logs/TC-1107.txt` | Исключение: дубль BUG-311 |
| `run-logs/TC-1201.txt` | Исключение: недоступен платёжный стенд → не баг продукта |
| (нет лога) TC-1150 | Ошибка: неполные данные → вернуть QA-инженеру |
| `expected-outcomes.md` | Эталон решений по каждому упавшему кейсу и пример черновика репорта |

Логи хранятся как `.txt`, потому что `*.log` исключены в `.gitignore`.
