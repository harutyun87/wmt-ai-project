# Шаг 0. Инициализация проекта

Выполняется один раз до раздела 1 ТЗ-паспорта. Занимает 10–15 минут.

**Зачем.** Все девять промптов паспорта предполагают, что уже есть учебная папка, в ней — описание процесса, а Codex знает правила работы. Шаг 0 создаёт это заранее, чтобы:

- каждый раздел опирался на файлы, а не на память чата;
- можно было продолжить в новом чате без потери контекста;
- в разделе 5 был git-diff для ревью;
- секреты и реальные данные не попали в проект с самого начала.

**Вход:** выбранный процесс, ноутбук с Codex, Python 3 и git (желательно).
**Выход:** папка проекта с правилами, заполненной карточкой процесса и первым коммитом; Codex подтвердил правила и задал вопросы по пробелам.

## Порядок действий

| # | Шаг | Кто | Результат | Проверка |
|---|---|---|---|---|
| 0.1 | Выбрать процесс | Участник | Название и владелец (роль) | Критерии выбора ниже выполнены |
| 0.2 | Создать папку проекта | Участник (скрипт) | Структура папки, `AGENTS.md`, `PROCESS.md`, `STATUS.md`, `.gitignore`, git | Скрипт вывел «git init + первый коммит» |
| 0.3 | Заполнить карточку процесса | Участник ± Codex | `PROCESS.md`, 1–3 файла в `data/synthetic/` | Нет реальных данных и секретов; неизвестное помечено |
| 0.4 | Запустить Codex и передать правила | Участник → Codex | Codex пересказал правила и карту разделов | Пересказ совпадает с `AGENTS.md` |
| 0.5 | Проверить готовность | Codex → Участник | Список пробелов в `QUESTIONS.md`, `STATUS.md` обновлён | Критерии готовности выполнены |
| 0.6 | Зафиксировать | Участник | Коммит `раздел 0: карточка процесса` | `git log` показывает коммит |

### 0.1 Выбор процесса

Процесс подходит, если:

- он ваш: вы знаете его шаги или можете спросить исполнителя;
- повторяется (не реже раза в неделю) и у него понятные старт и результат;
- эффект можно измерить: время, ошибки, задержки, ручные операции;
- его можно показать на вымышленных данных без потери смысла;
- первая версия умещается в практикум: 5–15 шагов, 1–3 системы.

Не подходит: разовые проекты, процессы целиком «в голове» без входа и выхода, процессы, где без реальных ПДн нельзя показать даже пример.

### 0.2 Создание папки

```bash
python3 init_project.py ./my-process --name "Сверка счетов поставщиков" --owner "Руководитель казначейства"
cd my-process
```

Скрипт безопасно запускать повторно: существующие файлы он не перезаписывает.
Нет Python — распакуйте готовый шаблон `project-template/` и замените `<название процесса>` в `AGENTS.md` и `PROCESS.md`.

Что создаётся:

```
AGENTS.md         правила для Codex: принципы, карта «раздел ↔ блок ↔ артефакт», требования к артефактам
PROCESS.md        карточка процесса — вход для раздела 1
STATUS.md         трекер разделов 0–9
QUESTIONS.md      открытые вопросы
DECISIONS.md      принятые решения (только подтверждённые)
RUN.md            команды запуска (заполняется в разделах 6, 8)
.gitignore        .env, ключи, data/real/, logs/
.env.example      имена переменных без значений
docs/ skills/code-review/ review/diffs/ src/ tests/ data/synthetic/ logs/
```

Codex автоматически читает `AGENTS.md` в корне папки, поэтому правила из стартового промпта паспорта действуют в каждом чате, а не только в первом.

### 0.3 Карточка процесса

Заполните `PROCESS.md` сами или пройдите интервью с Codex (промпт ниже). Минимум для раздела 1: название, зачем бизнесу, старт, вход, результат, роли, объём (хотя бы оценка) и один синтетический пример.

### 0.4–0.5 Запуск Codex и проверка готовности

Откройте Codex **в папке проекта** и отправьте промпт «Старт». После этого переходите к разделу 1 паспорта в том же чате.

## Промпты

### Старт (вместо стартового промпта паспорта, один раз)

```
Помоги мне сделать автоматизацию своего процесса: от описания работы до MVP и плана на 30/60/90 дней. Мы на шаге 0 — инициализация.

1. Прочитай AGENTS.md, PROCESS.md и STATUS.md.
2. Перескажи правила работы в 5–7 пунктах и карту «раздел ↔ блок занятия ↔ артефакт».
3. Проверь PROCESS.md: чего не хватает для раздела 1 (AS IS), что противоречит само себе, есть ли признаки реальных данных или секретов.
4. Задай вопросы по пробелам — не больше 7, самые важные первыми. Ответы, которые я дам, внеси в PROCESS.md; то, на что я не знаю ответа, — в QUESTIONS.md.
5. Обнови STATUS.md для раздела 0 и скажи, готовы ли мы к разделу 1.

Ничего, кроме PROCESS.md, QUESTIONS.md, STATUS.md и файлов в data/synthetic/, на этом шаге не создавай. Решения принимаю я.
```

### Интервью (если PROCESS.md пуст)

```
Проведи со мной короткое интервью, чтобы заполнить PROCESS.md. Задавай по 2–3 вопроса за раз, в порядке разделов карточки. Если я отвечаю «не знаю» — не додумывай, отметь и перенеси в QUESTIONS.md. Если я называю реальные имена, контрагентов, номера документов — предложи обезличенную замену. В конце создай 1–3 синтетических примера в data/synthetic/: обычный случай, исключение и ошибку.
```

### Продолжение в новом чате

```
Продолжаем проект ТЗ-паспорта в новом чате. Прочитай AGENTS.md, STATUS.md, PROCESS.md и артефакты разделов со статусом «проверен». Кратко: какие разделы приняты, что открыто в QUESTIONS.md, какой следующий раздел и чего для него не хватает. Ничего не меняй, пока я не отправлю задание.
```

Если у вас только итоговый паспорт Markdown из HTML-тетради — положите его в `docs/passport.md` и добавьте в промпт: «Принятые разделы — в docs/passport.md; разложи их по файлам артефактов из AGENTS.md и покажи, что получилось, до записи».

## Критерии готовности шага 0

- [ ] Папка создана, в ней `AGENTS.md`, `PROCESS.md`, `STATUS.md`, `.gitignore`.
- [ ] `PROCESS.md` заполнен минимум для раздела 1; цифры помечены как замер или оценка.
- [ ] Есть хотя бы один синтетический пример в `data/synthetic/`.
- [ ] В проекте нет реальных ФИО, контрагентов, номеров документов, токенов и паролей.
- [ ] Codex пересказал правила и карту разделов без искажений.
- [ ] Пробелы, которые пока нельзя закрыть, перечислены в `QUESTIONS.md`.
- [ ] Сделан коммит `раздел 0: карточка процесса`.

## Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Codex не следует правилам | Открыт не в папке проекта | Перезапустите Codex из корня папки, где лежит `AGENTS.md` |
| Скрипт: «коммит не создан» | Не задан автор git | `git config user.name "..."`, `git config user.email "..."`, затем закоммитьте |
| Codex «придумал» цифры объёма | Нет данных в карточке | Попросите заменить на «не знаю» и перенести в `QUESTIONS.md` |
| Раздел 7 (риски) раньше реализации | Порядок блоков занятия: риски — блок 4 | Делайте по TO BE и технологиям с пометкой «предварительно», пересмотрите после раздела 6 |
| Промпт ссылается на «блок 6/7» | Номера блоков ≠ номера разделов | Карта соответствия — в `AGENTS.md` |
