## 1. Запускаемая версия

bugdraft 0.1.0, `src/bugdraft/`, только стандартная библиотека Python 3.10+.

```powershell
$env:PYTHONPATH = "src"
python -m bugdraft analyze --run data/synthetic/test-run-RUN-2026-11-16-01.csv --bugs data/synthetic/existing-bugs.csv --out out
python -m bugdraft decide  --out out/RUN-2026-11-16-01 --case TC-1042 --action approve --severity Major
python -m bugdraft decide  --out out/RUN-2026-11-16-01 --case TC-1107 --action approve
python -m bugdraft publish --out out/RUN-2026-11-16-01
```

Сквозной пример (выполнен 2026-11-17): 10 кейсов → 4 предложения (новый баг, дубль BUG-311, вернуть QA-инженеру, окружение) → 4 решения → outbox: `issue__TC-1042__2.14.0-rc3.json`, `note__TC-1107__2.14.0-rc3.json`. Повторный publish: «записано 0, пропущено 2».

**Факт:** с реальной моделью не запускалось — в среде проверки нет модели и сети.

**План проверки (30 мин, на машине участника):**

## 7. Ограничения и ручной резерв

| Ограничение | Ручной резерв |
|---|---|
| Нет записи в трекер: только outbox | QA переносит issue/note из outbox в трекер вручную (копировать title, description, labels) |
| Нет интеграции с TMS | Экспорт CSV из TMS вручную после рана |
| Скриншоты не анализируются | Прикладываются к задаче вручную |
| Поиск дублей лексический | QA проверяет кандидата; при сомнении — поиск в трекере как в AS IS |
| Компонент по тегам лога, иначе `unknown` | QA указывает компонент при переносе |
| Маскирование по шаблонам не ловит имена и адреса | Выборочная проверка черновиков (SECURITY-CHECKLIST, «При работе» п. 5) |
| Если bugdraft недоступен | Процесс AS IS полностью сохраняется |
